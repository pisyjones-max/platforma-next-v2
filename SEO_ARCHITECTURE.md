## 1. Текущая архитектура (на момент аудита)

Стек: Next.js App Router, каталог читается в рантайме из `public/catalog/catalog.json` (`src/lib/catalog.ts`), ISR `revalidate = 600`.

| Тип страницы | Route | Кол-во | Индексируется |
|---|---|---|---|
| Главная | `/` | 1 | да |
| Категория | `/catalog/[catSlug]` | 133 (122 с товарами) | 122 (11 пустых → noindex) |
| Группа категорий | `/catalog/group/[groupSlug]` | 22 | да |
| Товар | `/catalog/[catSlug]/[productId]` | 6 094 | да |
| Бренд | `/catalog/brand/[brandSlug]` | 76 | да |
| Хаб брендов | `/catalog/brand` | 1 | да |
| Город (доставка) | `/dostavka/[city]` | 6 | да |
| Блог | `/blog/[slug]` | по числу статей | да |
| Статические | `/about`, `/delivery`, `/loyalty-card`, `/dizayn-proekt` | 4 | да |

**Итого посадочных страниц:** ~6 337 (без учёта товаров: ~243).

Каталог: 133 категории, 6 094 товара, 22 группы. Данные обновляются ночным парсером (`mk4s.ru` → инкрементальный апдейт), не пересобирая сайт.

Уже реализовано (см. историю правок):
- Динамический `sitemap.ts` — главная, статические, города, блог, группы, бренды, категории (кроме пустых), товары
- `robots.ts` — закрывает `/api/`, `/_next/`, `/admin/`
- `canonical` на всех динамических страницах через `generateMetadata`
- Schema.org: `Organization` (HardwareStore), `WebSite`, `BreadcrumbList` (везде), `Product` (карточки товара), `FAQPage` (главная, `src/lib/faq.ts`)
- Бренд-страницы (`src/lib/brands.ts`) — агрегируют товары бренда по всему каталогу, а не только внутри одной категории
- Городские страницы (`src/lib/cities.ts`) — уникальный контент на каждый город, не шаблонные дорвеи
- Пустые категории (11 шт.) — noindex + дружелюбный UI вместо «Ничего не найдено»

## 2. Семантика: что показал Wordstat

13 073 очищенных запроса (после фильтрации мебельного/медицинского/аниме-шума — см. `seo/build_seo_map.py`), суммарная частотность ≈ 5,72 млн/мес по выборке (кровля, сайдинг, фасад, Технониколь, Grand Line, Docke).

### Интент
Подавляющее большинство запросов в нише стройматериалов — **commercial** (голый товарный запрос без явных маркеров в этой вертикали почти всегда транзакционный). Отдельно выделены:
- **commercial+informational** — пользователь ещё не выбрал материал (типичный пример — «фасад дома»)
- **informational** — «как», «какой выбрать», «сколько нужно» и т.п.
- **geo+commercial** — запрос + город (72 запроса, см. раздел 5)

**Важная оговорка по «Фасад дома» (1,53 млн):** слово «фасад» в чистом виде (388К) остаётся смешанным по интенту, несмотря на фильтрацию — часть трафика по «фасады», «фасады мдф», «матовые фасады» и т.п. исторически относится к кухонной мебели, не к строительным фасадам. В `seo-map.csv` такие строки помечены в колонке `action` пометкой «ВНИМАНИЕ: смешанный интент» и понижены до P1 (не P0), чтобы не завышать ожидания от этого кластера искусственно. Рекомендация: смотреть не на сырую частотность головного слова, а на длинный хвост (`фасад дома`, `отделка фасада`, `штукатурка фасада`, `плитка для фасада` и т.д. — там интент чистый и коммерческий).

## 3. Разрыв семантика ↔ каталог

### Категории, которые нужно создать (спрос есть, товара нет)
1. **Наплавляемая/рулонная кровля** (35 860/мес) — техноэласт, унифлекс. Сейчас частично прячется в «Гидроизоляции» (24 товара из 6 094).
2. **Жидкая резина / жидкая кровля** (19 219/мес) — сейчас смешана с «Герметиками и мастиками».
3. **Клинкерная плитка/кирпич** (24 223/мес) — категория «Фасадная плитка» существует, но не выделяет клинкер явно (41 товар на весь спрос).

Создание категорий требует реальных SKU от поставщика — **бизнес-решение**, не техническое. Технически структура каталога (`catalog.json` → группы → категории) уже поддерживает добавление новых категорий без изменения кода.

### SEO-хабы, которые нужно создать (intent commercial+informational, не листинг товаров)
1. **`/fasad/fasad-doma`** — 1,53 млн/мес. Помогает выбрать материал (сайдинг vs плитка vs клинкер vs штукатурка), затем ведёт в конкретные категории. См. раздел 4.
2. **`/fasad/sajding`** — 1,05 млн/мес. Сейчас есть только страницы по типу материала (`/catalog/vinilovyy` и т.д.), нет страницы уровня «сайдинг вообще», которая бы их все связывала и объясняла разницу.
3. **`/catalog/group/krovlya`** — существует, но это технический листинг без сравнительного контента (нет «мягкая vs металло vs фальцевая — что выбрать», нет FAQ). Частотность головного слова «кровля» — 1,1 млн/мес.

### Пустые категории (11 шт.) — решено технически
`stenovye-paneli-pvh`, `otsinkovannye`, `greyushchiy-kabel`, `krovelnye-lestnitsy`, `avariynye-lestnitsy`, `perekhodnye-mostiki`, `ograzhdenie-krovli`, `fotozabory`, `laminat`, `plintus-napolnyy`, `vetonit` — выставлен `noindex`, исключены из sitemap, показывают дружелюбный UI с CTA вместо «Ничего не найдено». Как только появится товар — категория автоматически станет видимой (без правок кода).

## 4. Рекомендуемая структура SEO-хаба «Фасад дома»

Не листинг товаров, а страница выбора (соответствует принципу ТЗ: «поисковый запрос → полезная посадочная → выбор материала → категория → товары»):

```
H1: Отделка фасада дома — материалы и цены

Краткое вступление (что учитывать при выборе)

Варианты отделки (карточки-переходы):
  → Сайдинг (винил/металл/фиброцемент/цоколь)  → /fasad/sajding
  → Фасадная плитка / клинкер                   → /catalog/fasadnaya-plitka
  → Термопанели                                  → /catalog/termopaneli-fasadnye
  → Утепление фасада                             → /catalog/uteplitel
  → Сэндвич-панели                               → /catalog/sendvich-paneli

Сравнительная таблица (материал / цена за м² / срок службы / монтаж)

FAQ (вентилируемый vs мокрый фасад, нужно ли утепление, сколько стоит под ключ)

CTA: Рассчитать стоимость / Позвонить
```

Технически: серверный компонент, переиспользует существующие паттерны (`breadcrumbSchema`, `jsonLdScriptProps`, CSS-токены `var(--surface)` и т.д.), без нового фреймворка.

## 5. Гео-SEO

Найдено 72 геозапроса (город/область + товар/бренд), суммарно ~15К/мес — то есть гео сам по себе не основной канал, но точечно значим. Основные города по частоте: Раменское, Коломна, Воскресенск, Люберцы — **все уже покрыты** страницами `/dostavka/[city]` (`src/lib/cities.ts`).

Новых городских страниц по этому аудиту **не требуется** — расширять только при появлении реального спроса в будущих выгрузках Вордстата (см. принцип ТЗ п.24 — не плодить дорвеи).

## 6. Приоритизация (P0–P3)

Логика: `P0` = высокая частота (≥10К/мес) + категория полностью покрыта → усиливать контент/метатеги. `P1` = либо высокая частота без страницы (создавать), либо частичное покрытие. `P2`/`P3` — длинный хвост, обрабатывается контентом внутри уже существующих страниц (title/description/FAQ), не отдельными URL.

| Приоритет | Кол-во кластеров | Что делать |
|---|---:|---|
| P0 | 8 | Страница есть — усилить метатеги/H1/контент под конкретные топ-запросы кластера |
| P1 | ~20 | Либо создать хаб/категорию (гэпы выше), либо расширить контент частично покрытых страниц |
| P2/P3 | остальное | Покрывается длинным хвостом в title/description существующих категорий, отдельные URL не нужны |

Полная построчная таблица — `seo/seo-map.csv` (13 073 строки, колонки: `keyword, frequency, cluster, intent, page_type, url, existing, action, priority, city`).
